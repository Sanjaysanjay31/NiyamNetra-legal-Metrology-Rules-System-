# requirements-render.txt — deploy set for Render's free Python runtime.
#
# Same as requirements.txt MINUS the four packages that cannot work there:
#
#   paddlepaddle / paddleocr  ~1.5 GB installed. Render free has a 512 MB RAM
#                             build+run ceiling, so the build either times out
#                             or the service OOMs on first request.
#   pytesseract               needs the `tesseract-ocr` system binary; the
#                             native Python runtime has no apt-get.
#   pyzbar                    needs `libzbar0`, same reason.
#
# This is safe because every vision import in the app is lazy — they live inside
# the scan-upload endpoint bodies, not at module level — so `uvicorn main:app`
# boots, and auth, inspections, records, reports (PDF/DOCX/XLSX/CSV) and /health
# all work.
#
# What you LOSE: nothing crashes, but nothing is read either. ocr_engine.run_ocr
# tries Paddle, falls back to Tesseract, and returns engine="none" with a
# failure_reason when both are missing; rules_engine fails open, so every check
# comes back not_assessed instead of compliant/violation. And because a scan
# whose overall_result is not "violation" has its images purged, a not_assessed
# scan keeps no photo either. So this deploy set is for auth / records /
# dashboard / report demos — do the actual capture-and-assess demo against a
# local or LAN backend, which has the full requirements.txt installed.
#
# Middle path if you want real OCR on Render: switch the service to a Dockerfile
# that does `apt-get install -y tesseract-ocr libzbar0`, then install this file
# plus pytesseract==0.3.10 and pyzbar==0.1.9. Tesseract is small enough for the
# free instance; PaddleOCR is not, at any tier below a paid one.
